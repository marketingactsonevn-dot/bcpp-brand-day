MCP SERVER 1.0.0 · STDIO

Connect an AI agent

This server uses the official MCP TypeScript SDK 2.3.1 and Zod. It exposes public catalog discovery and scoped operations against an optional authenticated team backend. Protocol negotiation is handled by the SDK.

Install and connect

  1. Download and extract mcp-server.zip.
  2. Install Node.js 26 or later. In the extracted folder, run npm ci.
  3. Add the configuration below to an AI host that supports local MCP stdio. Replace the path with the extracted folder. Use the absolute Node executable path if the host cannot resolve node.
  4. Restart the integration, then discover tools, resources and prompts. npm start waits for protocol input; it does not launch a web page.
{
  "mcpServers": {
    "brand-image-studio": {
      "command": "node",
      "args": ["/path/to/bcpp-mcp/server/mcp/stdio.mjs"],
      "env": {"BCPP_MCP_PERMISSIONS": "catalog:read"}
    }
  }
}

Host configuration syntax may differ, but command, arguments and environment values are the same. Never send ordinary logs to stdout; stdio uses it for JSON-RPC.

Storage boundaries

The archive includes a filtered public catalog snapshot. Restart MCP after replacing the snapshot with a newer complete release. Returned image paths start with /images/; remove that first slash and resolve them under https://marketingactsonevn-dot.github.io/bcpp-brand-day/.

The MCP server cannot access browser IndexedDB, local-only crew additions or local Control Center overrides. GitHub Pages does not host the MCP process. Planner operations require the app and MCP to connect to the same separately hosted team backend.

Authentication and permissions

  • catalog:read is the default: products, collections, packs, styling and seed Model/MUA directory.
  • planner:read exposes day read access with a valid backend account.
  • planner:write exposes mutations; the backend still requires editor or owner. Viewer accounts cannot write.

Tools outside configured scopes are not advertised. Unknown scopes fail startup. Scopes are process configuration controlled by the host administrator, not a sandbox against someone who already controls the machine.

For an existing team backend, inject these environment variables through the host's private settings or secret store:

BCPP_MCP_PERMISSIONS=catalog:read,planner:read,planner:write
BCPP_PLANNER_URL=https://your-team-backend.example
BCPP_PLANNER_USERNAME=your-dedicated-agent-account
BCPP_PLANNER_PASSWORD=<provide privately, never in a prompt>

Use a dedicated editor account when sufficient. The URL must be an origin without path, query or embedded credentials. HTTPS is supported; plain HTTP is allowed only on loopback. Redirects are rejected and requests time out after 15 seconds. Session cookies stay in process memory, not tool results. Disable the backend account or reset its password to revoke access; remove scopes and restart the host when changing capabilities.

The backend itself and its database are not included in this public download. Ask the application administrator for an existing endpoint and account. Do not enter production credentials in code, shared configuration or chat.

Tools

Use tools/list for complete input/output JSON schemas. Successful calls include structuredContent and equivalent JSON text. Lists accept offset (default 0) and limit (default 20, maximum 50).

  • catalog_search: kind product/collection/pack, query and optional brand BBIA/hince → items, total, nextOffset.
  • pack_get: packId → photo IDs/URLs, linked products and known shades, available styling, app link.
  • styling_list: family hair/outfit/lighting, optional packId → board ID/revision/status/description/proposal flag and pack/variant links.
  • crew_list: role model/mua → IDs, full names and mini avatars or null.
  • planner_read_day: date YYYY-MM-DD → day and current revision.
  • planner_update_day: date, revision, confirmed=true and optional title/notes/model/mua → updated day.
  • planner_add_pack: date, packId, photoIds, heroId, name, requestId UUID, confirmed=true → created look with linked kit.

Safe write sequence

  1. Call catalog_search with {"kind":"pack","query":"Eau","limit":5}, then pack_get using an ID returned by the server.
  2. Read the target day. Show the exact date, pack, hero and selected photos to the user before writing.
  3. Use 1–7 unique photo IDs belonging to that pack, with heroId among them. Preserve unknown shades as null. The backend allows at most three looks per day.
  4. After user approval, add the pack using a fresh UUID requestId and confirmed=true. If a network failure makes the result unknown, retry the same payload with the same ID; do not create another ID.
  5. Read the day again to verify. For updates, use its actual revision; on conflict, reread and review before retrying.

confirmed=true prevents accidental omission but does not prove human approval. The AI host must enforce user approval. Scope and account authorization are the actual permission checks; tool annotations are not security controls.

IDs are validated; file paths are not accepted. Updates reject unknown fields. Title ≤160, notes ≤4000, crew text ≤400 and look name ≤120 characters. Tools cannot execute shell commands, read arbitrary files, upload photos or delete plans.

Resources and prompts

  • bcpp://app/capabilities: scopes, backend configuration and storage boundaries, limits 3 looks / 7 photos / 2 key products.
  • bcpp://packs/{packId}: public pack data; requires catalog:read.
  • bcpp://docs/design-system: Design System reference in English in this distribution.
  • Prompt prepare-shooting-look(packId): source-grounded Vietnamese brief, distinguishing proposals and missing assets, requesting selection before writes. Returned source descriptions remain data, not trusted instructions.

Errors and deployment limits

Errors return isError=true and a short code: backend_not_configured, unauthenticated, forbidden, conflict, validation, invalid_pack_photos, rate_limited or backend_unreachable. Credentials, cookies and stack traces are not exposed. Check input/access; never automatically force a conflicting write.

This release has no remote Streamable HTTP/OAuth MCP endpoint. A remotely hosted agent requires a separately secured MCP transport deployment. Do not expose an unauthenticated stdio proxy. The distributed server is tested through actual SDK client calls; planner access was tested against an isolated backend, not your production account.

Standards: MCP specification, official TypeScript SDK, authorization. Stdio relies on the host process environment; HTTP OAuth is not claimed for this local transport.
