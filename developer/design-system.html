DESIGN SYSTEM 1.0

Paper, light & clarity

Use a warm paper surface, charcoal typography and generous space around photography. Keep the scrapbook album, brand logos and original image colors. Avoid decorative form gradients and unnecessary gray product cards.

Tokens

  • Color: page #F5F3F0, panel #FFFEFC, primary text #191918, secondary text #68665F, subtle border #E3E0DA. Semantic success, warning and error colors always accompany text or an icon.
  • Typography: Newsreader for editorial headings; Be Vietnam Pro for body and controls; JetBrains Mono for short metadata. Sizes 11, 12, 14 and 16px; titles 28–38px. Body line height 1.55.
  • Spacing: 4, 8, 12, 16, 20, 24, 32, 40 and 48px. Field gap 8px, control gap 8–12px, section gap 24–32px. Leave at least 16px between library header controls and the detail divider.
  • Shape: radii 6, 10, 16, 28 and pill. Low, panel and popover shadows indicate layers; mini product photos do not need their own shadow.
  • Interaction: control heights 32px compact, 36px default and 44px touch. Motion 140/220ms, reduced to zero under reduced-motion preference.

tokens.css defines primitives and semantic roles. Consume roles such as --surface-panel, --text-secondary and --focus-ring. Compatibility aliases --bg/ink/muted/line/card/wash connect existing app components to the same system. Do not duplicate primitive values in feature styles.

Components and states

  • Button: secondary, primary and danger; default, hover, pressed, keyboard focus and disabled. Explicitly set submit when required; the default is type=button.
  • IconButton: accessible label required; 16px currentColor SVG, stroke 1.4. Existing app icon-button geometry supplies the circular target.
  • SearchField: label, controlled value and onValueChange; container focus ring, native search clear and disabled state.
  • Segmented: labeled group of buttons with aria-pressed and optional disabled options. Use for mode switching; do not claim tab semantics without tab panels.
  • Field: linked label, hint and error; connect aria-invalid and aria-describedby. Display actionable validation near the field, not only in a tooltip.
  • Existing domain components: Dialog, CrewPicker, GroupPicker, LibraryPanel and planner controls retain their specialized logic while sharing semantic tokens and interaction rules.

Responsive and content rules

At 600px and below, use 16px panel gutters and stack fields. From 601–980px, keep tablet header groups aligned; above 980px, use the desktop layout. Wrap tool groups instead of shrinking icons. Popovers and dialogs must stay within the viewport.

Linked products use at most four columns. Product kit avatars stay 56px wide inside a wider column; plan and PDF photo frames remain 3:4. Long fitting descriptions scroll within a stable detail region so album pagination does not jump. Do not change limits, callbacks or stored data for a visual adjustment.

Developer and AI workflow

  1. Find an existing component and semantic token before introducing another.
  2. Preserve native labels, buttons, disabled states and visible keyboard focus. Keep errors readable.
  3. Keep business state and API behavior unchanged; update layout in the owning component.
  4. Review hover, focus, active, disabled and error states in the interactive catalog.
  5. Run type checks and affected UI regressions; inspect actual desktop/mobile screenshots. Geometry checks do not certify visual quality.
