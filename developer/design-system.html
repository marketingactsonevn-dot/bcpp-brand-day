DESIGN SYSTEM 1.1 · 27 OCTOBER 2026

Paper, light & clarity

Use a warm paper surface, charcoal typography and generous space around photography. Keep the scrapbook album, brand logos and original image colors. Avoid decorative form gradients and unnecessary gray product cards. A row shows at most two visible controls; secondary actions live in a ⋯ menu.

Tokens

  • Color: page #F5F3F0, panel #FFFEFC, album #FBFAF7, subtle #EFECE7, highlight #FBF3E8; primary text #191918, secondary text #68665F (at least 4.88:1 on every surface). Divider #E3E0DA; control boundary #8A8479 (at least 3:1). Success, warning and error colors always accompany text or an icon.
  • Typography: Newsreader for editorial headings; Be Vietnam Pro for body and controls; uppercase JetBrains Mono for short metadata. Sizes 11, 12, 14 and 16px; titles 28–38px; body line height 1.55. Sentence text never below 11px, mono labels never below 10px.
  • Spacing: 4–48px scale. Field gap 8px, control gap 8–12px, section gap 24–32px, at least 16px between a header and its divider.
  • Shape and depth: radii 6, 10, 16, 28 and pill; low, panel and popover elevation. Layers --z-raised · overlay · dropdown · notice · sheet · toast · popover · context (1 · 6 · 20 · 30 · 40 · 60 · 80 · 1000); native dialog and popover elements use the top layer.
  • Interaction: controls 32px compact, 36px default, 44px touch under pointer: coarse. Motion 140/220ms with --ease-standard, zero under reduced motion. Breakpoints 480, 600 and 980px (literal in media queries).
  • Images: --frame-aspect 3 / 4 for every plan and PDF frame; kit thumbnails 56px (48px below 480px). Crops are stored per image id; source pixels never change.

tokens.css defines primitives and semantic roles. Consume roles such as --surface-panel, --text-secondary, --border-control and --focus-ring. Compatibility aliases --bg/ink/muted/line/card/wash/ctl connect existing components to the same system; when you override a token locally, set the semantic token and its alias together. New code uses semantic names.

Components and states

  • Button: secondary, primary, danger and quiet; default, hover, pressed, keyboard focus, disabled and aria-pressed. The default is type=button.
  • IconButton: label required and should name the object; aria-pressed makes it a toggle and fills the star icon. Icons: close, search, chevron, info, more, plus, star.
  • Menu: one ⋯ trigger for a row's secondary actions. Items take a label, onSelect, optional disabled or danger, plus separators. Native popover provides light dismiss, Escape and focus return; arrow keys, Home and End move between items. Anchored to the trigger on wide screens, a titled bottom sheet at 600px and below.
  • SearchField: label, controlled value and onValueChange; container focus ring, native clear, disabled state.
  • Segmented: a labeled group of aria-pressed buttons. Do not claim tab or radio semantics without tab panels or arrow-key handling.
  • Field: linked label, hint and error with aria-invalid and aria-describedby. Show actionable validation near the field.
  • Domain components: Dialog, Help, shade/group/product/crew/date pickers, Library album, product kit and calendar keep their specialised logic and share semantic tokens. Popover surfaces use the panel background, subtle border, 16px radius and popover elevation.

Patterns

  • List row with a photo: a 3:4 thumbnail that opens its picker (dashed empty slot with +), name and uppercase meta, a shade chip, a quiet auto-growing note, then Key ★ and ⋯. Several shades of one product form a group with one head (name, shade count, picker, reorder) and one row per shade.
  • Navigation: browsing context lives in the URL; Back and in-app back buttons agree; Escape in a search box only affects that box.
  • Autosave and conflicts: changed fields are sent with their base value; offline edits retry; conflicts offer keep mine or use theirs; leaving a screen mid-save still completes it.
  • Upload, crop, export: preview before saving; 3:4 framing with 1–4× zoom; export waits for unsaved edits and reports missing information.
  • Destructive actions: recoverable where possible (undo, recently deleted), otherwise last in a menu.

Responsive and content rules

At 600px and below use 16px gutters and stacked fields; 601–980px tablet; above 980px desktop. Wrap tool groups instead of shrinking icons; keep popovers and dialogs inside the viewport. Long names wrap in lists; truncate only inside one-line controls and expose the full text. Keep product names and source shade/edition codes; never infer a shade from a photo. Linked products use at most four columns.

Developer and AI workflow

  1. Find an existing component and semantic token first; add a new primitive to controls.tsx/css with a catalog example.
  2. Prefer native semantics: labels, buttons, disabled, aria-invalid, visible focus, native popover.
  3. Keep business state, limits and API behavior unchanged; change layout in the owning component.
  4. Review hover, focus, active, disabled and error states, both languages, long text and touch in the interactive catalog and the real screens.
  5. Run type checks and affected regressions in a fresh browser profile; inspect real desktop, tablet and phone screenshots. Geometry checks do not certify visual quality.
